❯ Act as an expert Java and LibGDX game developer. I am building a 2D

  I need you to design and implement the enemy AI, state machines, and hitbox
  systems for four specific enemies. I also need a dedicated LibGDX `Screen` to

  ### 1. Project Context & Architecture Rules
  * **Engine:** Java with LibGDX.
  * **Interfaces:** I already have a `Damageable` interface in my project. You
  should use this, and you are free to define any other interfaces (e.g.,
  `EnemyAI`, `Renderable`) or abstract base classes (e.g., `BaseEnemy`) to keep
  the code DRY and OOP-compliant.
  * **Hitboxes:** All hitboxes must be implemented using standard Rectangles
  (`com.badlogic.gdx.math.Rectangle`). Any collision with an enemy's hitbox
  should deal damage to the player.
  * **Animations:** Do NOT use a centralized "God Class" for animations.
  Encapsulate the texture loading, `Animation<TextureRegion>`, and state-time
  tracking directly within each specific enemy class (or a dedicated component
  inside them).
  * **Death States Explanation:** You will see `DEAD_AIR` and `DEAD_LAND`
  states. `DEAD_AIR` is the animation played when an enemy is killed in mid-air
  (they are falling). `DEAD_LAND` is the animation played when an enemy dies
  on the ground, or when an airborne dead enemy finally hits the ground. Your
  state machines should handle this physics transition.
  * **Assets:** Assume all textures exist.

  ### 2. The Enemies & AI Logic
  Please implement the following four enemies in separate classes based on this
  behavior logic:

  #### Enemy 1: Crystal Crawler (Ground Enemy)
  * **Logic:** Moves in a straight line at a constant speed. It ignores the
  player's position. If it hits a wall or reaches the edge of a cliff, it turns
  around and walks in the opposite direction.
  * **States to implement:** `WALK`, `TURN`, `DEAD_AIR`, `DEAD_LAND`.

  #### Enemy 2: Mosquito (Flying Enemy)
  * **Logic:** Has a defined rectangular vision range (field of view). If the
  player enters this range, it tracks them. When it spots the player, it
  records the player's exact momentary position, pauses briefly (Attack
  Anticipate), and then swoops/dashes in a straight line to that exact point.
  It CANNOT change direction mid-swoop. The attack ends when it reaches the
  point, hits a wall, or a timer expires.
  * **States to implement:** `IDLE`, `TURN`, `ATTACK_ANTICIPATE`, `ATTACK`,
  `DEAD_AIR`, `DEAD_LAND`.
