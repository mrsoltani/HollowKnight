# 2026-08-08

- Added downward-pointing map laser hazards. New files: `LaserHazard` (state machine IDLE → WINDUP → FIRING with per-hazard randomized off/charge/on durations; shared laser atlas + ChargedOrb assets; beam stops on the highest solid block whose top is below the spawn; damage band recomputed each frame; one damage application per activation cycle, respecting player god mode and invincibility) and `LaserSpawnData` (carrier for spawn point in game-space y-up coordinates).
- Extended `TiledMapHelper.getLaserSpawns()` to read the `laserSpawn` object layer, supporting `PointMapObject`/`RectangleMapObject`/generic objects, applying the same Tiled-y-down → game-y-up flip used by the boss door (`wy = mapPixelHeight - py`), and honoring optional `width`/`height` object properties.
- Wired lasers into `GameScreen`: `initLasers` parses spawns and clears old hazards on `loadRoom`, `updateLasers` ticks each laser and consumes a single damage application per cycle via `consumeDamageOnPlayer`, lasers render between spikes and background particles, and `drawHitboxes` (D key) shows the spawn bar (gray/yellow/red by state) plus the live damage band in scarlet. `LaserHazard.disposeSharedAssets()` is called from `GameScreen.dispose()`.
- The existing `CrystalPeak02.tmx` already authors the `laserSpawn` layer with four points (LASER_01..LASER_04). No asset edits needed; the code is general and will spawn lasers on any map that defines the layer. `:core:compileJava` and `git diff --check` passed.
- Fixed laser beam rendering bug reported as "I can only see the circular orb not the laser the orb just sits at the start." Two coordinate bugs in `LaserHazard`:
  1. `computeBeamEnd` initialized `bottom = top - 0.001f`. Combined with the loop's `if (bottom >= r.y + r.height) continue;` (which wants `bottom` to be the highest block-top seen so far), every valid block below the spawn was skipped, leaving `bottom ≈ spawnY` and producing a hairline 0.001f-tall beam. Changed to `Float.NEGATIVE_INFINITY` so the first matching block always wins, with a fallback to `0f` (room floor) when no block is found so unobstructed lasers still render.
  2. FIRING damage-band was set up as `damageBand.y = spawnY; damageBand.height = Math.max(0f, endY - spawnY)`. In LibGDX y-up, `endY < spawnY` (beam goes DOWN), so `endY - spawnY` was negative and clamped to 0 — a zero-height rect that never overlapped the player. Flipped to `damageBand.y = endY; damageBand.height = Math.max(0f, spawnY - endY)`.

# 2026-08-08 (later)

- Reverted the previous laser fix and rewrote `LaserHazard` from scratch because the codebase is **y-down screen-pixel coords throughout**, not LibGDX y-up. Concrete evidence: player collision uses `bounds.y = b.bounds.y + b.bounds.height` for "land on top of block" (which is y-up at the codepath, but the rest of the file uses screen pixels end-to-end — the convention is internally consistent); solid blocks, enemy spawns and player spawns are all read directly from Tiled without flipping. The boss door applies a `1080 - y` flip in `BossDoor` constructor as a one-off for its own map. My first fix assumed y-up and produced an inverted coordinate system that broke both the beam length and the damage band.
- Reverted `TiledMapHelper.getLaserSpawns()` to drop the `wy = mapPixelHeight - py` y-flip so the spawn sits at exactly the Tiled-authored y, matching how player / enemy / block coords flow into the game.
- Rewrote `LaserHazard.computeBeamEnd()` for y-down: iterate blocks, find the smallest `r.y` strictly above `spawnY` among those that horizontally overlap the spawn (block's BOTTOM is `r.y + r.height`; blocks entirely above the spawn skip via `r.y + r.height <= spawnY`). Sentinel `Float.POSITIVE_INFINITY` means "no blocker"; the FIRING branch clamps with `LASER_MAX_LENGTH = 4000f`.
- Reworked the FIRING damage band: `damageBand.y = spawnY` (TOP of band in y-down screen pixels), `damageBand.height = max(0, clampedEndY - spawnY)`.
- Rewrote `render()`: beam rect has fixed `LASER_VISUAL_HEIGHT = 28f` thickness (matching CrystalGuardian's `LASER_VISUAL_HEIGHT`) and a length of `clampedEndY - spawnY`. The muzzle-burst atlas slice (u = 160/228..184/228) is now drawn NARROW and TALL instead of wide and short, so the same horizontal wisp becomes a thin vertical beam. Orb is centered on `spawnY` (no +12f offset, matching CrystalGuardian's `gunX, gunY` orb).
- Net effect: the Crystal Guardian long-beam visual style — a thin wispy pillar dropping out of a pulsing circular orb — now matches in these downward map lasers. Damage band is now a full rectangle from spawnY down to the closest blocker (or to MAX_LENGTH), so the D-toggle debug overlay shows a proper tall hitbox rather than a one-pixel line.
